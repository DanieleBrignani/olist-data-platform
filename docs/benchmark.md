## Method

* 3 repetitions. Each starts from an **empty** database (meta/raw/src truncated, dbt schemas dropped, `VACUUM`), then runs the initial load, then a rerun with the same files.
* Steps are the same functions the Prefect flow calls, timed without orchestrator overhead.
* Query latency: client-side wall time as `olist_reporting` on the published schemas, 1 warm-up + 20 timed runs each.
* Determinism: every repetition fingerprints all published tables (row count + md5).
